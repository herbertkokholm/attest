An LLM ensemble screens your review —
and the run has to prove its own recall.

A standalone, dependency-light Python kernel for the screening-and- self-validation step of systematic-review title/abstract screening. An ensemble of LLMs from different vendors rates each record; disagreement escalates to a human; three statistically separated planes make sure recall is estimated only from a random, gold-checked sample of what got excluded — never from adjudication or active-learning data. Every run produces a versioned self-validation record: inter-rater agreement, error correlation, escalation rate, and recall with its worst-case floor.

How it works

Vote, aggregate, and never auto-exclude on uncertainty

Records that survive a caller-supplied prefilter go to an ensemble of vendor Raters; the boundary+dispersion rule (attest.ensemble.aggregate.g) aggregates each vote vector into an auto-label or an escalation. There is deliberately no "exclude" option in that rule — auto-excluding on ensemble uncertainty is the one disposition that would silently destroy recall.

1. PrefilterDeterministic, source-agnostic dedup and exclusion rules the caller injects — owns the upstream PRISMA counts.
→
2. Ensemble voteEach vendor rates the record on an ordinal scale (exclude / uncertain / include); votes aggregate via the boundary+dispersion rule.
→
3. Decide or escalateA mean of exactly zero escalates to a human by default — it never auto-commits to a final label.

Escalated and low-confidence records are routed by two of three statistically separated planes; the third is the only one recall may ever be estimated from.

Human resolution
attest.planes.adjudication
Resolves an escalated (disagreement) record with an authoritative human label.
Never a probability sample
attest.planes.active_learning
Routes high-disagreement records, or unanimous records with low within-vendor confidence, to human review — to improve the ensemble, not to measure it.
Only source of recall
attest.planes.recall_audit
Refuses any row not tagged PLANE_RECALL_AUDIT — the one random, gold-checked sample recall may ever be estimated from.

Quickstart

Install, check, and run the bundled example

No PyPI release yet — install from a checkout. The bundled four-vendor example config and gold set run entirely offline via --deterministic-seed, no vendor API keys required.

Install
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
Run the checks
ruff check .
ruff format --check .
mypy src
pytest -q
python tools/check_boundary.py
Screen the bundled example data
attest screen \
  --input data/example_gold_set.json \
  --config data/example_config.json \
  --run-dir /tmp/attest-demo \
  --deterministic-seed 42

Architecture

Dependency-light, and each module does one thing

PrefilterDeterministic, source-agnostic dedup and exclusion rules, injected by the caller; owns the upstream PRISMA counts.
EnsembleRuns each vendor's Rater and aggregates the vote vector via the boundary+dispersion rule — never auto-commits an uncertain mean to a final label.
Three separated planesadjudication, active_learning, recall_audit form a firewall so recall is never estimated from a biased sample.
ProvenanceFive separately versioned descriptors and the machinery around them: config, epochs, changelog, protocol, manifest, sentinel, runs.
StatsKrippendorff's alpha, error correlation, and stratified recall with a rule-of-three worst-case floor.
I/OThe only module that touches a filesystem: a local, idempotent JSON run directory.
VendorsThe Rater protocol, a network-free DeterministicRater for tests, and live adapters for six vendor families — the sole path to the network.
Batch modeBatchRater drives vendors' async batch APIs at roughly 50% cheaper cost, producing byte-identical votes and decisions to the synchronous path.
tau as a step functionattest.ensemble.tau proves tau only attains a finite set of behaviorally distinct values per ensemble size, and derives a safe one from policy instead of a hand-picked decimal.
Confidence signalPer-vote logprobs from vendors that support them, scored only once at least 3 vendors return one — feeds confidence-stratified auditing and active-learning selection.
CLIFile-based subcommands over a run directory; only screen and batch-fetch ever reach the network.

Integrity

Why the firewall needs care

Three statistically separated planes were a deliberate design choice, and it comes with a real risk this project is built around rather than around ignoring.

Mechanically enforced boundarytools/check_boundary.py statically scans every module and fails CI if a kernel module imports a scheduler, database, web framework, or — outside attest.vendors — a network client.
Zero never auto-excludesA vote vector whose mean is exactly zero either escalates to a human or folds into +1 — there is deliberately no path from ensemble uncertainty to an auto-exclude.
Recall audit is the only sourcerecall_audit.build_strata refuses any row not tagged PLANE_RECALL_AUDIT; adjudication and active-learning selections are firewalled out of the recall estimator.
Run directories are epoch-lockedRunStore.write_config/ write_epoch both refuse a second, different value — a deliberate config change always means a new run directory, never an in-place edit.
Append-only changelogwrite_changelog refuses any write that would rewrite or shrink stored history; every epoch change is logged as initial_config, explicit_config_change, or sentinel_drift.
Offline integrity verificationattest verify recomputes a SHA-256 per persisted artifact from the run manifest and exits 1 — no traceback — if anything is missing or changed, so CI can gate on it directly.
